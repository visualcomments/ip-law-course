# Skill: building-agent-ready-course-repo

Библиотека проверенных приёмов для создания и ведения **открытого
учебного репозитория курса**, рассчитанного на работу ИИ-агента
(co-learner / harness типа botai), с **верифицированным корпусом
источников**, RAG-индексом на Google Диске и безопасной публикацией.
Сформирована по итогам реального проекта («История России: история и
философия науки и технологий», 30 занятий).

## Когда применять

- строишь заново или поддерживаешь репозиторий курса для агента;
- нужно: корпус цитируемых текстов + автоматическая проверка цитат,
  RAG-индекс, его распространение без серверов (Google Диск),
  очистка репозитория от внешних брендов/локальной инфраструктуры.

## Принципы

1. **Верифицируемость.** Каждая прямая цитата — дословно из корпуса,
   с координатами «файл · фрагмент #N», и проверяется скриптом
   (покрытие ≥ 0.92 против letters()-нормализованного текста).
2. **Агент-первым.** Корень репозитория — понятный `AGENTS.md`
   (карта, контракт цитирования, команды); рядом машиночитаемая
   программа (`syllabus.json`), трек и прогресс по конвенции harness,
   навыки-зеркала `.agents/`, `.claude/`, `.cursor/`, `tools/` + `Makefile`.
3. **Портативность.** В репозитории нет локальных путей, имён хостов,
   IP, реальных URL, серверных схем. Всё внешнее — через переменные
   окружения (`FALT_CORPUS_ROOT`, `FALT_INDEX_URL`, `FALT_VENV_PY`, ...).
4. **Самодостаточность индекса.** Индекс (Annoy + эмбеддинги + чанки +
   config) упаковывается в архив и распространяется через **Google Диск**:
   манифест с SHA-256 + инструмент `index-fetch` (скачивание, проверка
   суммы, атомарная установка). Никакого сервера для поиска не нужно.
5. **Тредмарк-безопасность.** Никаких упоминаний вузов и их подразделений;
   при реальной необходимости — переписывание истории (`git filter-repo`
   + force-push) и переименование репозитория.

## Процедура (чек-лист)

1. **Корпус.** Только публичное достояние / правительственные документы
   (NASA, правительство США, классика 19 — нач. 20 вв.). Конвертация
   в `txt/` (в т.ч. DjVu). Запрещённые ©-файлы вычищать сразу.
2. **Индекс.** Нарезка на чанки → эмбеддинги (fastembed, запас:
   CPU-параллельность пулом процессов) → Annoy (angular).
   Поддерживать `index_prune` (вырезание файлов без пересчёта
   эмбеддингов: фильтр строк + пересборка annoy).
3. **Верификация.** `verify_quotes.py`: парсинг «Цитата/Источник»,
   fuzzy-сопоставление по letters(); ускорение — префикс-фильтр чанков
   (`ql[:24] in chunk.ltext`) вместо полного difflib по всем чанкам.
   Прогон до 0 ошибок, обновлять `verification/REPORT.md`.
4. **Agent-адаптация.** AGENTS.md, syllabus.json, track/progress,
   tools (search/index-fetch/verify/session/assignment/status),
   Makefile, навык `using-course-corpus` (если курс — про корпус).
5. **Индекс на Google Диске.** Собрать архив (`course-index-<дата>.zip`),
   посчитать SHA-256 для архива и каждого файла, записать
   `index-manifest.json` (с полями размер/хэш/url), выложить на Диск
   («любой, у кого есть ссылка»), вписать url. Файлы-источники на диске
   листать в документе `docs/GOOGLE-DRIVE.md` с контрольными суммами.
6. **index-fetch** (та же папка проекта): скачивание по share-ссылке или
   uc-ссылке; обязательная проверка SHA-256 ДО распаковки; атомарный
   swap (`index` → `index_old`, распаковка → `index`); sanity-вывод
   (`n_chunks`, `n_files`).
7. **Публикация.** Перед push: глобальный grep запрещённых терминов
   (вузы, бренды, «физико-технические», имена хостов, IP) → 0.
   Описание репозитория на GitHub тоже чистое. При переписывании
   истории: `git bundle`-бэкап → `git filter-repo --replace-text`
   (файл правил строго UTF-8!) → `--force`, re-add origin →
   `git push --force origin main`; проверка pickaxe'ем `git log -S`.
   Переименование репо — `gh api -X PATCH ... -f name=...` + set-url.

## Проверенные подводные камни

- **OCR-артефакты**: двойные слоги («воспи- воспитавший»), колонтитулы,
  вставки иллюстраций — нормализация letters(), приёмлемо точное
  совпадение ≥ 0.92; НЕ пересказывать цитату своими словами.
- **Правила filter-repo в ANSI ломают замену**: PowerShell `Add-Content`
  пишет не-UTF8; правила писать через write-инструмент (UTF-8), иначе
  кириллица не сматчится.
- **Google Диск для больших файлов**: страница «Virus scan warning»
  (confirm=t, `drive.usercontent.google.com/download` + uuid). Без `gdown`
  нужен свой flow; краткий тест-скачивание (html? sha? размер?) до
  полного прогона.
- **Windows-окружение**: перед перезаписью `annoy.index` убивать python
  (mmap-лок); после batch-правок — `py_compile`; внутри PowerShell
  вложенные `python -c` с кириллицей ломаются — писать скрипты-файлы.
- **git-filter-repo**: после `--replace-text` хеши меняются (все коммиты
  переписываются), origin удаляется — заново `remote add` + force-push;
  локальные копии пользователей нужно переклонировать.
- **Первый Drive-файл от пользователя** может отличаться от ожидаемого
  (перезаписан/другой архив): сверять hash архива И содержимое —
  только при совпадении распаковывать (иначе обновить манифест).

## Быстрые команды

```bash
make help                       # цели
make index-fetch URL="<ссылка>" # скачать индекс с Google Диска (манифест/вызов)
make search QUERY="..."         # поиск по корпусу
make verify                     # проверка цитат (0 ошибок — норма)
make session n=NN / make assignment n=NN
# история:  git bundle create B --all && git filter-repo --replace-text rules.txt --force
#           git remote add origin <url> && git push --force origin main
```
